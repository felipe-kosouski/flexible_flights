## 1. Purpose

The Candidate Selector decides which date pairs are worth sampling from the full date grid.

It is responsible for:

- Enforcing API call limits
- Preserving temporal coverage
- Producing deterministic, explainable selections

It is the first layer of product intelligence.

---

## 2. Inputs

The selector receives:

- **date_pairs** — Array of [departure_date, return_date], typically generated by Search::Sampling::DateGrid
- **max_candidates** (Integer) — Maximum number of date pairs allowed for sampling
- **strategy** (Symbol) — One of:
  - :balanced (default, MVP)
  - :nomad (future, not implemented yet)

---

## 3. Outputs

```
Array<[Date, Date]>
```

Where:

- Size ≤ max_candidates
- Order is deterministic
- No duplicates
- All pairs come from input

---

## 4. Pre-Conditions

- Input date_pairs may be empty
- Input may exceed max_candidates
- No validation errors are raised

---

## 5. Selection Strategy — MVP (:balanced)

### 5.1 Goal

Maximize date coverage while minimizing sampling bias.

---

### 5.2 Core Rules

1. If date_pairs.size ≤ max_candidates: return all pairs (unchanged)
2. Otherwise: select pairs evenly across the departure date range

---

### 5.3 Algorithm (Normative)

Let:

- pairs_by_departure = date_pairs.group_by(&:first)
- departure_dates = sorted unique departure dates
- D = departure_dates.count

**Step 1 — Allocate slots per departure date**

Compute:

```
base_slots = max_candidates / D (integer division)
remainder  = max_candidates % D
```

Each departure date receives base_slots, plus 1 extra slot for the first remainder dates (chronological).

**Step 2 — Select return dates**

For each departure date group:

- Return dates are sorted ascending
- Select earliest return dates first
- Do not exceed allocated slots

---

### 5.4 Determinism Rules

- No randomness
- Chronological ordering always wins
- Same input → same output

---

## 6. Ordering Guarantees

Final output must be ordered by:

1. departure_date ASC
2. return_date ASC

---

## 7. What CandidateSelector Must NOT Do

- 🚫 Call flight APIs
- 🚫 Know about airlines
- 🚫 Know about prices
- 🚫 Use heuristics like "cheap days"
- 🚫 Persist anything

It operates only on dates.

---

## 8. Edge Cases

| Case                                   | Behavior                     |
|----------------------------------------|------------------------------|
| Empty input                            | Return empty array           |
| max_candidates = 0                     | Return empty array           |
| More departure dates than max_candidates| Some dates get 0 slots       |
| Single departure date                  | Fill using earliest returns  |
